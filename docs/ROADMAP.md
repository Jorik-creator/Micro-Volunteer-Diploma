# Roadmap покращень (осінь 2026)

Узгоджений план розвитку. Словник — у [CONTEXT.md](../CONTEXT.md), ключові рішення — у [docs/adr](adr/).

## Етапи

Статус (вересень 2026): етапи 1–8 виконано; для етапу 9 код готовий (`seed_demo`, `render.yaml`, S3-сховище), розгортання — за [DEPLOY.md](DEPLOY.md).

1. **Баги та інфраструктура** — виправлення з аудиту, `django-environ`, WhiteNoise, CI (ruff + pytest + `makemigrations --check`).
2. **Життєвий цикл запиту** — сервісний шар, нові стани, вихід/зняття волонтера, двостороннє завершення, періодичні задачі.
3. **Оцінки** — двосторонні, прихований обмін, теги, нагадування.
4. **Довіра** — рівні L0–L2, підтвердження email, заявки на верифікацію, коди організацій, премодерація, черга модерації, скарги.
5. **Розмови** — чат 1:1 після прийняття, ручний обмін номером.
6. **Email** — Brevo через anymail, налаштування сповіщень у кабінеті, скидання пароля.
7. **Дизайн** — доступність для літніх, чистка CSS, прототипи ключових екранів.
8. **Приватність** — політика, правила, згода, самовидалення акаунта з анонімізацією.
9. **Деплой і демо** — Render + Neon + Supabase + Brevo + cron-job.org, `seed_demo`, демо-вхід, щоденне скидання.

## Життєвий цикл запиту

| Стан | Значення |
|---|---|
| `draft` | Чернетка отримувача рівня L0 |
| `pending_moderation` | Очікує премодерації (перші 3 запити отримувача L1) |
| `rejected` | Відхилено модератором (з причиною) |
| `active` | Опубліковано, набір волонтерів |
| `in_progress` | Набрано потрібну кількість волонтерів |
| `awaiting_confirmation` | Усі прийняті волонтери позначили «виконано» |
| `completed` | Підтверджено отримувачем або автоматично через 72 год |
| `cancelled` | Скасовано отримувачем або модератором |
| `expired` | Минув час: `active` — після `needed_date`; `in_progress` — через 7 днів після `needed_date + тривалість` |

Переходи відгуку волонтера: `pending → accepted | rejected | withdrawn | closed`, `accepted → withdrawn | removed`.

- Прийняття, коли набрано потрібну кількість → запит `in_progress`, решта `pending` → `closed`.
- Вихід або зняття прийнятого, коли прийнятих стало менше за потрібну кількість → запит знову `active`.
- Скасування/прострочення → усі `pending` → `closed`, усім учасникам сповіщення.
- Отримувач може підтвердити завершення з `in_progress` чи `awaiting_confirmation`, або повернути `awaiting_confirmation → in_progress` («ще не виконано»).
- Редагування: лише `draft`/`pending_moderation`/`active`. Якщо є відгуки — формат, дата й адреса заблоковані; `volunteers_needed` не менше кількості прийнятих (якщо дорівнює — перехід у `in_progress`).
- Нагадування обом сторонам через 24 год після `needed_date + тривалість`, якщо запит ще `in_progress`.

## Оцінки

Пари: отримувач ↔ кожен волонтер, що лишився прийнятим на момент завершення. Вікно 14 днів від завершення. Видимість — коли обидві сторони пари написали або вікно минуло. Зірки 1–5, теги, необов'язковий коментар.

## Доступ

| Дія | L0 | L1 | L2 |
|---|---|---|---|
| Перегляд запитів, карти | ✓ | ✓ | ✓ |
| Чернетка запиту | ✓ | ✓ | ✓ |
| Публікація запиту | — | премодерація перших 3 | ✓ |
| Відгук на запит без візиту додому | — | ✓ | ✓ |
| Відгук на візит додому | — | — | ✓ |

## Розмови

1:1 отримувач ↔ прийнятий волонтер у межах запиту. Лише текст до 1000 символів, посилання некліканими, polling 5 с при активній вкладці, сповіщення не частіше 1 на 10 хв на розмову. Після завершення/скасування/зняття — лише читання 14 днів. Модератор бачить розмову тільки за скаргою.
